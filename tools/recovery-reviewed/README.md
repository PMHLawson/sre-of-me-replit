# Reviewed recovery source archive

[SOMR-429](https://pmhlawson.atlassian.net/browse/SOMR-429) preserves these exact reviewed source bytes alongside the additive storage candidate in [PR12](https://github.com/PMHLawson/sre-of-me-replit/pull/12). This archive has no runtime hook. Its capture entrypoint remains disabled. The sources depend on the original private review job layout, catalog inputs, installed Replit tooling and a separately reviewed execution wrapper; this directory is not a portable recovery CLI. The manifest records each archived file's byte count and SHA256.

The migration targets an existing six-table installation. Its comment-only baseline cannot initialize an empty database. The additive SQL creates eleven empty tables with twenty-two foreign keys and two normal migration ledger entries. The existing migrator creates its ledger before the SQL transaction; a failed application must retain evidence and stop without ledger stamping, dropping, restoring or retrying. Production release, tenant ownership, seeding and historical backfill are separate work.

The reviewed gate compares legacy columns by name for semantic compatibility while preserving their actual physical order and the complete catalog, privileges and legacy record identity/content. It permits only the precisely linked internal foreign-key triggers added to users. Full expected catalog and ledger comparisons follow application. A second normal migration run must leave all rows, catalog and ledger unchanged. The keyed fingerprint helper uses every reviewed composite component in order, C collation for text and numeric order for the integer ledger key. The legacy fingerprint function remains unchanged.

Recovery capture holds one read-only exported snapshot while a full custom-format database dump and the complete comparison inventory stream into authenticated encrypted artifacts. Full decode-to-null and authenticated full-length/digest checks are required; a successful capture or decryption check is not an actual restore test. The COMPLETE receipt is published only after all success conditions, using exclusive creation, full-write handling, synchronization and owned-artifact cleanup. Ten offline receipt failure cases and fourteen synthetic keyed-fingerprint cases verified these reviewed components.

An explicitly quiet application workflow, absent owned listeners/descendants, no other database clients and fresh platform-selected binding proof are required around execution. Restart is a separate gate after preservation acceptance and startup-retention inspection. Neither an idle query snapshot nor a running-app fingerprint is a substitute for the quiet baseline.

Recovery private keys stay local. Comparison keys and continuation references stay in private owned state outside the workspace and served roots. Owner catalogs, counts, fingerprints, database bindings, process/environment data, ciphertexts, receipts, credentials and raw logs are deliberately excluded from this public source archive. Public certificate digests embedded in the reviewed generic code identify its intended recipient; no certificate or key file is included.
